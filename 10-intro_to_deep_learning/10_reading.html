1The neuron

One unit that weighs inputs, sums them, and decides.

A neuron multiplies each input by a weight, adds a bias, and passes the sum through an activation function. Stack neurons into layers, layers into a network — and learning means nudging every weight so the final error shrinks. Backpropagation is that blame assignment: gradients flow backward from the error, telling each weight which way to move, exactly as the board lectures derive step by step.

Neural Network from Scratch.ipynb
output = activation(np.dot(w, x) + b) # one neuron, NumPy only

2Networks from scratch

No libraries, no magic — earn every abstraction.

Two notebooks build the machinery by hand: basic neuron → layer of neurons → full network, first as a single learning unit with regression and classification examples, then as a multi-layer network. Slow on purpose — after this, Keras calls feel like shortcuts you understand instead of spells you memorize.

Why suffer through scratch first?

Frameworks hide exactly three things: the forward sum, the backward gradient, and the weight update. Having written all three by hand, every Keras option in §3–§4 maps to a line you once debugged yourself.

3First networks with Keras

The same ideas, at real speed, on real image data.

The MNIST notebook builds the first classifier — data loading, a Sequential stack of layers, model summary, an alternative building style, training with a history object — and the Fashion-MNIST notebook repeats the arc on harder images while adding the professional toolkit: initializers, regularizers, callbacks, early stopping, model checkpointing, predictions, and save/load.

the Keras rhythm
model = keras.Sequential([...layers...]) # stack it model.compile(optimizer=..., loss=...) # choose how it learns history = model.fit(X_train, y_train, epochs=...) # train, keep the history model.save('model.keras') # keep the winner
history

The returned object plots loss/accuracy per epoch — the training diary you read before touching any knob in §4.

save / load

A trained model is a file. Save it, reload it, predict without retraining — deployment starts here.

callbacks

Early stopping and checkpoints watch training while it runs — automation for the discipline §4 teaches.

4Practical tips for training

Three lectures of things that actually move the loss curve.

The tips notebook collects the practitioner's checklist: activation functions, batch normalization, optimizers, losses, L1/L2 regularization, dropout, early stopping, and model checkpointing.

When training stalls

Suspect the optimizer, the learning rate, and unnormalized inputs first — batch normalization and a better optimizer fix more runs than any architecture tweak.

When training overfits

The gap between train and validation curves is the diagnosis; L1/L2, dropout, early stopping, and more data are the treatment — in that order of cheapness.

5Project: bike sharing

Regression, tuned properly.

The capstone bike-sharing notebook runs the full arc on rental-demand data: quick exploration, preprocessing, classic ML baselines first (always know what "simple" scores before going deep), then the deep model — with Keras Tuner searching hyperparameters instead of hand-guessing them.

Baselines before brilliance

The notebook tries classic models before any neural net — if a tuned forest nearly matches the network, ship the simpler thing. Deep learning has to earn its complexity on every project.

◐Wrap-up — deep learning in one breath

The module compresses into a single loop.

the whole story
neuron (w·x+b) --> layers --> backprop gradients --> Keras stack --> fit + history --> tips (until curves behave) --> tune --> save
The one-sentence version

Deep learning is Module 09's fit/predict loop with learned features: neurons sum and activate, backpropagation assigns the blame, Keras stacks the layers, training tips tame the curves, tuning finds the knobs — and Modules 11 and 12 spend the payoff on images and text.
