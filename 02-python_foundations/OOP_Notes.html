1What is object-oriented programming?

A paradigm — a way of organizing a program.

OOP, or object-oriented programming, is a programming paradigm: a coding style, a way of organizing a program. The common paradigms are:

Procedural

A program as a sequence of steps — input, then step after step, then output.

Object-oriented

A program as objects and their interactions — each object bundles data with the code that uses it.

Reusable

Classes are written once and used many times.

Readable

Code is grouped around real things, not raw steps.

Maintainable

Fit for larger packages and applications.

Everything in Python is an object

Lists, strings, tuples, dictionaries, numbers, functions — and even classes themselves. You have been using objects since Module 02's very first notebook.

2What is an object?

An object has two parts: state and behavior.

the rule
# Object = State + Behavior # State -> attributes -> variables attached to the object # Behavior -> methods -> functions defined inside a class

State (attributes)

A player's name, a player's age, a customer's balance, an employee's job.

Behavior (methods)

Setting a player's name, changing a player's position, displaying an employee greeting.


Encapsulation is the act of bundling data together with the code that operates on that data:

encapsulation = data + methods
# A Player object stores the name AND knows how to change it class Player: def set_name(self, name): self.name = name

3Classes and instances

The blueprint, and the objects built from it.

Class

A blueprint or template used to create objects.

an empty class
class Player: pass # no implementation yet

Instance

A specific object created from the class.

two separate players
p1 = Player() # instance #1 p2 = Player() # instance #2 — a different object

p1 and p2 are separate objects, even though both were made from the same Player blueprint.

4Methods, attributes, and self

A method is a function defined inside a class — and self is who's calling it.

set_name
class Player: def set_name(self, name): # self = the instance that calls it self.name = name # self.name: an attribute on the object p1 = Player() p1.set_name("Ahmed") print(p1.name) # Ahmed
self

Refers to the current instance. It is conventionally the first parameter of every instance method — Python allows another name, but self is the standard.

p1.set_name("Ahmed")

Conceptually the same as p1.name = "Ahmed" — the method call sets the attribute for you.

dir(Player)

The built-in dir() inspects everything available on a class or object — its attributes, methods, and inherited names.

5The __init__ constructor

Initializing data at the moment an instance is created.

__init__() initializes instance data and is commonly called the class constructor — though strictly, Python creates the object before __init__() initializes it. Data is supplied while creating each instance:

Player with init
class Player: def __init__(self, name, age): self.name = name self.age = age p1 = Player("Ahmed", 29) # __init__ runs right now p2 = Player("Anas", 5) print(p1.name, p1.age) # Ahmed 29 print(p2.name, p2.age) # Anas 5 — each instance keeps its own values

A richer example straight from the notes — a customer with a job and a balance:

Customer
class Customer: def __init__(self, name, job, balance): self.name = name self.job = job self.balance = balance c1 = Customer("Abdo", "Engineer", 20_000) print(c1.job) # Engineer print(c1.balance) # 20000
Runs every time

The initialization code executes fresh for each new instance — every Customer(...) call re-runs __init__ with that call's arguments.

6The four core OOP principles

The pillars the whole object-oriented mindset rests on.

PrincipleMeaning
EncapsulationCombining data and the code that operates on it.
InheritanceExtending functionality from a parent class to child classes.
PolymorphismProviding a unified interface through methods with the same name.
AbstractionWorking with an outer interface while hiding implementation details.

6.1 Encapsulation

Data and the methods that use it live together in one class:

Customer with behavior
class Customer: def __init__(self, name, balance): self.name = name self.balance = balance def show_balance(self): # behavior belongs next to its data print(self.balance)

6.2 Inheritance

A child class receives the parent's functionality and adds its own:

parent → child
class Animal: def eat(self): ... def sleep(self): ... class Dog(Animal): # child = parent functionality MORE def bark(self): ...
"is-a" relationship

Not all class relationships are inheritance — a Dog is an Animal, so inheritance fits. Section 7 builds the concrete player example from the notes.

6.3 Polymorphism

Different classes expose methods with the same name, each implementing its own behavior.

same name, different behavior
class Football_Player: def shoot(self): print("kick the ball") class Tennis_Player: def shoot(self): print("hit the ball")

6.4 Abstraction

The user works with the object's visible interface — the internal details stay hidden.

interface vs details
engine.start() # visible interface # fuel mix, spark timing — hidden inside

7Inheritance

The player example done properly — a parent Player and a child AfricanPlayer.

The parent class holds general player functionality:

parent — Player
class Player: def __init__(self, name, age): self.name = name self.age = age def set_position(self, position): self.position = position def set_celebration(self, celebration): self.celebration = celebration

The child inherits all of that and adds its own attributes and methods:

child — AfricanPlayer
class AfricanPlayer(Player): # draws from Player def __init__(self, name, age, color, hair_style): super().__init__(name, age) # parent's constructor runs first self.color = color self.hair_style = hair_style def set_speed(self, speed): # brand-new for the child self.speed = speed player = AfricanPlayer(name="Ahmed", age=29, color="Brown", hair_style="Curly") player.set_position("Forward") # inherited player.set_celebration("Slide") # inherited player.set_speed(90) # own
super() vs. direct call

You can call the parent constructor directly with Player.__init__(self, name, age) — but super().__init__(name, age) is clearer and easier to maintain, especially in deeper hierarchies.

8Polymorphism

Both classes define set_name() — each with its own data and behavior.

Player

two names
class Player: def set_name(self, first_name, last_name): self.first_name = first_name self.last_name = last_name print(f"Name is set to {self.first_name} {self.last_name}")

Employee

one name
class Employee: def set_name(self, name): self.name = name print(f"Hello Mr. {self.name}")
same interface
p1 = Player() e1 = Employee() p1.set_name("Ahmed", "Mostafa") e1.set_name("Ahmed")
Output

Name is set to Ahmed Mostafa then Hello Mr. Ahmed.

Why it's useful

Both objects answer to the same method name — calling code can treat them uniformly while each class keeps its own implementation.

9Quick summary + combined example

The whole set of ideas in one program.

Objects

State (attributes) + behavior (methods).

Classes & self

A blueprint; self is the current instance.

__init__

Initializes each new instance's data.

Encapsulation

Data + methods that operate on it.

Inheritance

Child extends parent functionality.

Polymorphism

Same method name, class-specific behavior.

everything together
class Player: def __init__(self, name, age): self.name = name self.age = age def set_position(self, position): self.position = position def set_celebration(self, celebration): self.celebration = celebration def display(self): print(f"Player: {self.name}, Age: {self.age}") class AfricanPlayer(Player): # inheritance def __init__(self, name, age, color, hair_style): super().__init__(name, age) # parent constructor self.color = color self.hair_style = hair_style def set_speed(self, speed): self.speed = speed def display(self): # polymorphism — override print(f"Player: {self.name}, Age: {self.age}, " f"Color: {self.color}, Hair style: {self.hair_style}") player = AfricanPlayer(name="Ahmed", age=29, color="Brown", hair_style="Curly") player.set_position("Forward") player.set_celebration("Slide") player.set_speed(90) player.display()
The one-sentence version

Objects bundle state and behavior; classes are their blueprints; __init__ and self wire each instance up; and encapsulation, inheritance, polymorphism, and abstraction are the four organizing principles on top.
