1First programs & simple arithmetic

Your first program, and Python's operators and precedence.

00-simple_arithmetic.ipynb
print('Hello world!') print(2 + 2) 5 + 4 - 3 (2 * 3) + 4 10 / 2 (-7 + 2) * (-4)

* Parentheses tell Python to do those operations first.

exponent, quotient, remainder
# Exponentiation 2**5 # 32 9 ** (1/2) # 3.0 — square root # Integer division (quotient) 20 // 6 # 3 # Remainder (modulo) 20 % 6 # 2
Precedence order

From highest to lowest: ** (exponentiation) → *, /, //, % → +, - (evaluated left to right). Compare (-7 + 2) * (-4) = 20 with -7 + 2 * -4 = -15 — same numbers, different parentheses, different results.

The course also introduces the built-in numeric functions through a classic nested puzzle: min([sum([11, 22]), max(abs(-30), 2)]) — sum the inner list (33), take the max of the absolutes (30), then the min of the two (min(33, 30) = 30).

2Data types: scalar vs. non-scalar

Python is object-oriented, so everything is an object — and objects come in two broad flavors.

Python is an object-oriented language, so "everything is an object" — each object has a type that defines what programs can do with it. Objects are either:

Scalar

Cannot be subdivided — a single atomic value.

  • int — 100
  • float — 5.7
  • bool — True/False

Non-scalar

Have internal structure you can index or access.

  • str
  • list
  • tuple
  • dict
  • set
01-simple_data_types.ipynb
type(100) # <class 'int'> type(5.7) # <class 'float'> type(5 == 5) # <class 'bool'>

Type conversion (casting)

casting
float(3) # 3.0 int(3.1) # 3 — truncates, never rounds int('12541') # 12541 — string to int float('1.5') # 1.5

Boolean logic

Comparisons produce bool values and combine with and, or, and not — the same operators you'll reach for every time a model needs a condition:

boolean_logic
1 == 1 and 2 == 2 # True 1 != 1 or 2 == 2 # True not 1 == 1 # False

3Variables & assignment

Giving names to values — why, how, and what Python lets you do with them.

Variables let you reuse names instead of repeating values, and make changing code later easy. The course's running example is the area of a circle:

02-variables_assignment.ipynb
# Area of a circle pi = 3.14159 radius = 2.2 / 2 area = pi*(radius**2) radius = 3.2 / 2 # re-assign area = pi*(radius**2) # recompute — area doesn't know to update itself

Re-assignment

The old value may still be in memory, but the name now points elsewhere. A variable's value only changes when you run a new assignment.

Dynamic typing

a = 5; a = 'Hello' is legal — a name can hold different types over its lifetime.

in-place operators
radius = radius + 1 # legal — (=) is assignment, not equality radius += 1 # same thing, shorthand
= vs ==

= is assignment (give a name to a value). == is comparison (are two things equal?). Expect this mix-up to appear in your first bug — everyone's does.

4Strings

The first non-scalar type. If you want to use text in Python, you use a string.

A string is created by entering text between two single or double quotation marks. Backslashes escape characters, and \n is the newline symbol. input() returns a string — so you cast it with int() or float() when you need a number.

03-strings.ipynb
s = 'Hello, I_am learning_Python' s.split('_') # ['Hello, I', '', 'am learning', 'Python'] s.split() # split on whitespace # Concatenation 'Hi' + ', ' + 'friends' # Multiplication! 'Python' * 3 # 'PythonPythonPython'

Indexing and slicing

A string is a sequence of characters. Square brackets index it, and slicing uses [start:stop:step] — start defaults to 0, stop to len(s), step to 1:

indexing & slicing
s = 'I am different' s[0] # 'I' s[-1] # 't' — negative indexes count from the end s[0:3] # 'I a' s[0:8:2] # 'Imdf' s[::-1] # 'tnereffid ma I' — the "mirror" slice

Strings are immutable: s[0] = 'y' raises a TypeError. You rebuild instead:

immutability
s = 'hello' s = 'y' + s[1:] # 'yello' — a whole new string

String methods & formatting

methods & f-strings
s.upper() # 'HELLO' — returns new string 'A_B_C'.split(sep='_') # ['A', 'B', 'C'] name = 'Ahmad'; age = 30 print('My name is {} and my age is {}'.format(name, age)) print(f'My name is {name} and my age is {age}') # f-string — the modern way
Object.method()

Methods are functions belonging to an object — s.upper() acts on the string itself. This object-method shape is exactly what you'll see again in Module 09 with model.fit(X_train, y_train).

5Lists

Ordered, indexable, and mutable — the workhorse sequence.

04-lists.ipynb
num_list = [1, 2, 3] mix_list = ['A', 2, 3.7] # mixed types allowed num_list[1] += 4 # mutable — element changes num_list.append(3.5) # add to the end num_list.pop() # remove last (default -1) num_list.remove(3) # remove by value num_list.sort(); num_list.reverse()

Methods mutating in place

sort(), reverse(), append() change the list itself — contrast sorted(lst), which returns a new list.

String ↔ list

'Hello Python!'.split() → list; ''.join(msg_lst) → string; list('ABC') → ['A','B','C'].

Aliasing vs. cloning

Aliasing — dangerous

aliasing
hot = warm # both names, one list hot.append('pink') warm # now has 'pink' too!

Cloning — safe

cloning
cool = warm.copy() # a brand-new list cool.append('black') warm # unchanged

You can also nest lists to build matrices (matrix = [lst_1, lst_2, lst_3]) and unpack an unknown number of inputs with a starred name: a, *other = input('Numbers: ').split(',').

6Tuples

Ordered, indexable, and immutable — for things that must not change.

05-tuples.ipynb
t = (1, 2, 3) t.append(2) # AttributeError — no append on a tuple t[1] = 7 # TypeError — no item assignment t + (4,) # (1, 2, 3, 4) — new tuple; note the trailing comma # Unpacking & swapping x, y, z = (3, 4, 5) y, x = x, y # swap — no temp variable needed
Why tuples?

Use a tuple when the structure shouldn't change — e.g. a coordinate, a date, or a MLIST of things that are fixed. Code that expects immutability is easier to reason about.

7Dictionaries

Mappings of key → value, accessed by key, not position.

06-dictionary.ipynb
ages = {"Muhammad": 24, "Maryam": 42, "Anas": 58} ages["Anas"] # 58 ages.keys(); ages.values() ages['Ahmad'] = 31 # add a new entry mydict['Fruits'] = ['Apple', 'Orange', 'Banana'] # values can be lists # chained lookup puzzle primes = {1: 2, 2: 3, 4: 7, 7: 17} print(primes[primes[4]]) # 17

del and pop

del d[key] removes by key; d.pop(key, default) removes and returns the value — with a safe default if the key is missing.

No positional indexing

ages[1] raises KeyError — a dict is not a sequence.

+= doesn't merge dicts

ages += {'Ahmad': 31} raises TypeError. Use ages['Ahmad'] = 31 or .update() instead.

8Sets

Unordered collections of unique elements.

07-set.ipynb
y = {3, 5, 4, 3, 3} # {3, 4, 5} — duplicates removed y[0] # TypeError — not subscriptable # de-dupe a list set([1,1,2,2,3,4,5,6,1,1]) # {1, 2, 3, 4, 5, 6} set1.union(set2) # everything set1.intersection(set2) # shared set1.difference(set2) # in set1 only set1.issuperset(set2) # subset/superset tests
Sets in the real bootcamp

This is the end of the course's "Part 1" (data structures). Sets become genuinely useful later — e.g. faster membership checks than lists, and de-duplicating rows during preprocessing.

9If / elif / else

Part 2 begins: control flow — deciding what to do.

08-if_condition.ipynb
num = int(input('Enter an integer number: ')) if num >= 10: if num <= 100: # nested if print("Between 10 and 100") else: print('More than 100') else: print('Less than 10')

The equivalent "flattened" version using and:

flattened with and
if (num >= 10 and num <= 100): # same result as the nested version print("Between 10 and 100") elif num > 100: print('More than 100') else: print('Less than 10')

Indentation defines code blocks in Python — this is a language rule, not a style preference. The course's demo builds a simple calculator with an elif chain over a string operator ('+', '-', '*', '/'), which you'll rewrite as a loop (Section 10) and again as a function (Section 13).

10While loop

Repeat an action based on a check.

09-while_loop.ipynb
num = 1 # counter while num <= 10: print(num) num += 1 # very important — without it, infinite loop while True: # loop-and-break pattern for menus # ... run the calculator ... repeat = input(' Enter "y" for another operation or another key to break: ') if repeat == 'y': continue else: break

break

Breaks out of the closest enclosing loop.

continue

Goes back to the top of the closest enclosing loop (skipping the rest of the body).

pass

Does nothing at all — a placeholder for "implement this later."

11For loop & range

Iterate over any sequence — and loop over indices when you need them.

10-for_loop.ipynb
words = ["hello", "hi", "good morning", "good night", 1] for word in words: print(word) # iterate directly for index in range(0, len(words)): print(words[index]) # or iterate over indices. range(start, stop, step) for k, v in dic.items(): # dict iteration is hottest in practice print('{} >> {}'.format(k, v))

Iteration works over any sequence — strings (for _ in 'Hello'), lists, tuples, and dictionaries (.keys(), .values(), .items()). The section closes with the classic FizzBuzz exercise (1–100, "Fizz" for multiples of three, "Buzz" for multiples of five, "FizzBuzz" for both).

12List comprehension & enumerate

Two idioms that make Python code shorter and more readable.

List comprehension builds a list in one expression instead of a loop + append:

The long way

loop + append
lst = [] for num in range(1,11): lst.append(num**2)

Comprehension

one line
[num**2 for num in range(1,11)] [num**2 for num in range(11) if num % 2 == 0]
celsius → fahrenheit
celsius = range(10) fahrenheit = [((9/5)*temp + 32) for temp in celsius]

enumerate() returns the index and the value during iteration:

12-enumerate.ipynb
for i, letter in enumerate('Hello'): print("index {}: {}".format(i, letter)) # build an index dict — note duplicate 'l' overwrites its earlier index dic = {} for i, letter in enumerate('Hello'): dic[letter] = i dic # {'H': 0, 'e': 1, 'l': 3, 'o': 4}

13Functions

Part 3 begins: a block of code that is used more than once.

13-functions.ipynb
def circle_area(radius, PI = 3.14): # default parameter """ Function circle_area : calculates the area of circle Input: radius: the radius of circle Return: the area of circle """ return PI * (radius**2) circle_area(10) # 314.0 print(circle_area.__doc__) # docstrings are introspectable

Function vs. method

sorted(l) is a free function; l.sort() is a method owned by the list object. Both exist, subtly different.

Parameter vs. argument

The parameter is the name in the definition (radius); the argument is the value passed at the call (10).

Default values

PI = 3.14 gives a default, still overridable: circle_area(10, 3).

Docstrings

The triple-quoted block documents the function — and Python exposes it via .__doc__.

14*args & **kwargs

Functions that accept an undefined number of arguments.

14-args_and_kwargs.ipynb
def mean(*nums): # *args → tuple of positional args return sum(nums)/len(nums) mean(1,2,3,4,5) # 3.0 mean(*(range(100))) # 49.5 — splat/unpack a range into 100 args def data(**user): # **kwargs → dict of keyword args return user['hope'] data(name='ahmed', age=31, address='ABC', hope='football') # 'football'
Why this matters later

Scikit-learn's estimators are full of defaults and optional keyword arguments. Understanding **kwargs is how you'll read RandomForestClassifier(n_estimators=100, random_state=42).

15Scope & modules

Where a variable lives decides who can see it — and modules organize reusable code.

Local — doesn't change the global

scope
x = 5 def foo(): x = 10 # local x foo(); print(x) # 5 — global untouched

global keyword — modifies it

global
v = 5 def change_v(n): global v v = n # global v is changed change_v(50); print(v) # 50

16Recursion

Part 4 begins: defining something in terms of itself — and the base case that stops it.

Iterative — loop

for loop
fact = 1 for i in range(1, 6): fact = fact * i # 120

Recursive — call itself

factorial
def factorial(x): if x == 1: # Base case return 1 else: return (x * factorial(x-1))

The math that drives it: n! = n × (n-1)!. The base case (x == 1) is what prevents infinite recursion — every recursive function must eventually reach one.

Reading, writing, and appending text files — with context managers.

20What is OOP?

Python is an object-oriented language — everything is an object.

20-oop_what_is_oop.ipynb
a = 10; b = 3.25; c = "hi"; d = [1,2,3,5] print(type(a)) # <class 'int'> print(type(d)) # <class 'list'> s1 = 'hi'; s2 = 'bye' print(s1.upper()) # same method works on every instance of a class print(s2.upper())

Classes are blueprints

Predefined data types — int, str, list — are classes you already use.

Instances

a = 10 is an instance of the int class.

Methods belong to classes

Every instance of a class shares its methods — the class decides what "doing things" means.

From built-ins to your own

The whole point: pre-defined classes cover the basics, but you may need your own data type — that's what class definitions are for.

21Class anatomy: __init__, attributes, methods

The structure of a class — the blueprint for an object.

21-oop_class_anatomy.ipynb
class Customer: # blueprint for an object def __init__(self, name, age): # constructor — runs automatically self.name = name # instance variable (property) self.age = age # self = the instance being created def place_order(self): # instance method (behavior) print(f"{self.name} have placed an order") def cancel_order(self): print(f"{self.name} have cancelled an order") c1 = Customer("Mohamed", 30) c1.place_order() # Mohamed have placed an order isinstance(c1, Customer) # True

Attributes

Properties → variables the object carries (name, age).

Methods

Behaviors → functions the object can perform (place_order).

self

Refers to the instance that will be created later — c1 = Customer(...) passes c1 as self.

22The four OOP principles

Why use OOP at all — and the four pillars (abstraction, encapsulation, inheritance, polymorphism).

Procedural

Code as a sequence of steps. Great for data analysis and scripts.

Object-oriented

Code as interactions of objects. Great for frameworks and tools — maintainable, reusable code.

Abstraction & encapsulation

The user calls a method and gets a result — without needing to know the internal logic:

22-oop_principles.ipynb
class Employee(): def __init__(self, name, salary): self.name = name self.salary = salary def annual_raise(self, kpi_1, kpi_2, kpi_3): new_salary = self.salary + kpi_1 * 500 + kpi_2 * 1.5 + kpi_3 / 10 if new_salary > 20000: tax = new_salary * 0.2 else: tax = new_salary * 0.15 # many details may be here medical_insurance = new_salary * 0.10 social_insurance = new_salary * 0.15 self.salary = new_salary - (medical_insurance + social_insurance + tax) return self.salary emp1 = Employee('Anas', 10000) emp1.annual_raise(25, 120, 150) # one call — the details stay inside

Inheritance

Child classes inherit methods and attributes from a parent class — and can override them:

inheritance
class Manager(Employee): # inherits everything from Employee def __init__(self, name, salary): self.name = name self.salary = salary m1 = Manager("Ali", 40000) m1.annual_raise(50, 120, 150) # inherited from Employee, unchanged class Accountant(Employee): access_class = 'B' # class attribute def __init__(self, name, salary): super().__init__(name, salary) # call the parent's constructor def annual_raise(self, kpi_1, kpi_2, kpi_3): # override with different logic # different tax/insurance rates than Employee ...
Override

Create a method in a child class with the same name as the parent's and it takes precedence — the child may behave completely differently.

Polymorphism

"Same name, different behavior" — different classes expose a common method, each implementing it their own way:

polymorphism
class Football_Player(): def shoot(self): pass class Tennis_Player(): def shoot(self): pass # p1.shoot(), p2.shoot() — same name, different behavior

23The ML example — sklearn is just OOP

The payoff: everything you'll do in Modules 09–12 is calling methods on class instances.

23-oop_ml_example.ipynb
from sklearn.datasets import fetch_california_housing housing = fetch_california_housing() features = housing.data target = housing.target from sklearn.model_selection import train_test_split (X_train, X_test), (y_train, y_test) = train_test_split(features, target) from sklearn.linear_model import LinearRegression # import the Class reg1 = LinearRegression() # make an instance reg1.fit(X_train, y_train) # fitting method reg1.predict(X_test) # prediction method reg1.score(X_test, y_test) # scoring method # Swap the class, keep the interface — DecisionTreeRegressor has the same methods from sklearn.tree import DecisionTreeRegressor reg2 = DecisionTreeRegressor() reg2.fit(X_train, y_train) reg2.predict(X_test)
The full circle

LinearRegression is a class. reg1 and reg2 are instances. fit/ predict/score are methods — and both models share the same interface even though they behave differently (that's polymorphism). Everything in Module 09 builds on this exact pattern.

Before you move on — common beginner traps

Confusing = and ==: assignment vs. comparison.

Aliasing instead of cloning: hot = warm makes them the same list; use .copy() or slicing when you need independence.

Forgetting the mutating methods: s.upper() returns a new string — it does not change s. Strings are immutable; if you ignore the return value, "nothing happens."

Infinite while loops: an while True without a break (or a condition that never becomes false) never ends. Always ask: how does this loop terminate?

Unread file cursors: after my_file.read(), the cursor is at the end — call seek(0) before reading again, or use readlines().
