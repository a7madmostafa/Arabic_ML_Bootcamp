The pattern to copy

Every project here is functions + a loop + a main guard. Write one function per feature (display_word, deposit_money, scrape_books…), drive them from a while True loop, and shield it all with if __name__ == "__main__" so the script runs when executed and imports cleanly as a module.

P1Guessing Game

17:04 — your first program that plays with you. random picks a word, you guess it one letter at a time.

The game needs three little functions: pick a word at random, draw the partially-revealed word, and run the guess loop. The set guessed_letters remembers what you already tried — its uniqueness guarantee is exactly why sets were worth learning in Module 02.

CODE/01- Word Guess/guess_word.py
import random def choose_word(): words = ["python", "programming", "computer", "algorithm", "data", "science", "machine", "learning"] return random.choice(words) # one random pick def display_word(word, guessed_letters): display = "" for letter in word: # letter-wise rebuild if letter in guessed_letters: display += letter else: display += "-" return display # "p-----" style output def guess_word(word): guessed_letters = set() # letters already tried attempts = 0 while True: print(f"\nWord: {display_word(word, guessed_letters)}") user_guess = input("Enter a letter: ").lower() attempts += 1 if len(user_guess) != 1 or not user_guess.isalpha(): print("Invalid input! Please enter a single letter.") continue # skip, don't count it elif user_guess in guessed_letters: print("You already guessed that letter.") elif user_guess in word: print("Correct guess!") guessed_letters.add(user_guess) else: print("Incorrect guess. Try again.") if all(letter in guessed_letters for letter in word): print(f"Congratulations! You guessed '{word}' in {attempts} attempts.") break if __name__ == "__main__": guess_word(choose_word())
random.choice(words)

Picks one element from the list uniformly at random — the whole "surprise" of the game.

set() for guessed letters

Adding a letter twice is a no-op, and in membership tests against a set are fast. It makes every check below simpler.

all(...) generator

True only when every letter of the word is in guessed_letters — a one-line win condition.

continue vs break

continue sends a bad input back to the top (no attempt counted); break leaves the loop when you win.

P2Tic-Tac-Toe Game

24:01 — a two-player board game. The lecture has no CODE folder for this one, so you draw every line yourself.

A 3×3 board fits perfectly in a list: nine cells, players marking X or O by number. The two hard problems this lecture teaches are drawing the board and checking for a win after every move.

a board is just a list (representative drawing-stub)
board = [" "] * 9 # nine empty cells: indices 0…8 def draw(board): print(f" {board[0]} | {board[1]} | {board[2]}") print(" --+---+--") print(f" {board[3]} | {board[4]} | {board[5]}") print(" --+---+--") print(f" {board[6]} | {board[7]} | {board[8]}") # A win means one of the 8 winning lines is all-X or all-O: wins = [ [0,1,2], [3,4,5], [6,7,8], # rows [0,3,6], [1,4,7], [2,5,8], # columns [0,4,8], [2,4,6], # diagonals ] def winner(board, player): return any(all(board[i] == player for i in line) for line in wins)
Alternating turns

A turn variable toggling between "X" and "O", read a cell number with input(), and reject taken or out-of-range cells with continue.

any(...) over lines

winner() becomes one readable expression: is there any line where all three cells belong to the player?

Draw detection

If the board has no " " left and nobody has won, the game is a tie — a second condition in the same check.

Your Tic-Tac-Toe has no answer key

Unlike the other six projects, the repo ships no Tic-Tac-Toe code — build it live with the video and keep your solution for the portfolio. The lesson is the design process itself: data structure (a list of 9), a draw function, a win check, then the turn loop.

P3Simple ATM

8:19 — the shortest project, and the cleanest example of the menu-app skeleton: a balance you carry across menu choices.

One global balance shared by all functions, each feature in its own function, and a while True menu that keeps you inside the ATM until you press 4. Notice how withdraw_money protects against overdrawing.

CODE/03- ATM App/atm.py
balance = 0 def deposit_money(): global balance amount = float(input("Enter the amount to deposit: ")) balance += amount print(f"You have successfully deposited ${amount}") def withdraw_money(): global balance amount = float(input("Enter the amount to withdraw: ")) if amount > balance: print("Insufficient balance!") return # leave without touching balance balance -= amount print(f"You have successfully withdrawn ${amount}") def check_balance(): global balance print(f"Your current balance is ${balance}") def atm(): while True: print(""" 1. Deposit Money 2. Withdraw Money 3. Check Balance 4. Exit """) choice = int(input("Enter your choice: ")) if choice == 1: deposit_money() elif choice == 2: withdraw_money() elif choice == 3: check_balance() elif choice == 4: print("Goodbye!") break else: print("Invalid choice!")
float() not int()

Money has decimals — float reads "10.50", int would crash on it.

global balance

The module-level variable lives for the whole session; each function declares global only when it assigns to it.

Guard with return

An early return after "Insufficient balance!" stops the function before the overdraft line — no else needed.

Menu loop

The while True + numbered if/elif chain is the skeleton from the diagram — repeat it and you can build any CLI app.

P4Weather API

35:45 — your first real HTTP call. A city name goes out, live weather data comes back as JSON.

Three new ideas at once: the requests library, JSON responses, and keys slotted into a URL. The OpenWeatherMap endpoint is one f-string away:

CODE/02- Weather API/Weather_App.py
import requests def display_weather(data_dic): for key, value in data_dic.items(): print(f"{key.title()} : {value}") def get_weather_data(city): my_key = "<your-openweathermap-key>" url = f"https://api.openweathermap.org/data/2.5/weather?q={city}&units=metric&appid={my_key}" response = requests.get(url) data = response.json() # JSON → Python dict if data["cod"] != 200: return "City is not Found" print(f"## Weather in {data['name']} ##") return display_weather(data["main"])

The repo's second version, weather.py, wraps the same call in a while True "ask another city? (y/n)" loop, breaks out of it, and uses assert response.status_code == 200 to catch a bad request up front — a nice mash-up of Module 02's exceptions section.

API keys are secrets

In this lecture the key sits in the code — fine for a tutorial, bad for anything shared. The free OpenWeatherMap tier gives you a key; treat it like a password: paste it into your own file, and never commit it. P5 shows the professional way — an environment variable.

P5News API

11:52 — the same requests pattern, but now the key comes from an environment variable and the query lives in a params dict.

NewsAPI.org's top-headlines endpoint returns a JSON object whose articles list you walk with enumerate. Secrets ride in a .env file that python-dotenv loads at runtime — keeping the key out of the script entirely.

CODE/05- News API/news.py
import requests, os from dotenv import load_dotenv def get_top_headlines(api_key, keyword="technology", country="us"): url = "https://newsapi.org/v2/top-headlines" params = { "q": keyword, "country": country, "apiKey": api_key, } response = requests.get(url, params=params) if response.status_code == 200: articles = response.json().get("articles", []) for i, article in enumerate(articles[:10], start=1): # top 10 print(f"\nHeadline {i}") print("Title:", article["title"]) print("Source:", article["source"]["name"]) print("URL:", article["url"]) else: print("Error:", response.status_code) if __name__ == "__main__": load_dotenv() # reads your .env file api_key = os.getenv("API_KEY") get_top_headlines(api_key, input("Enter your News keyword: "), input("Enter the country code (e.g. 'us'): "))
params dict instead of a long URL

requests.get(url, params=...) builds the query string for you — safer and readable than string surgery.

articles[:10]

Slicing prevents printing the full 20+ articles — a tidy reminder that lists, tuples and API results all slice the same way.

enumerate(..., start=1)

Number the headlines from 1 instead of 0, like the header of a report.

os.getenv + .env

API_KEY=your-key lives in .env, loaded only in memory. Add .env to .gitignore so the secret never reaches GitHub — the setup you'll actually use at work.

P6Books Scraping

17:11 — the module's big one: pull an entire bookshop category off the web into a pandas DataFrame, paginating until you've captured every book.

This is web scraping in miniature: send a requests request, parse the HTML with BeautifulSoup, extract the bits you want, and hand them to pandas. The pipeline below is the shape every scraper in Module 04 will follow.

CODE/04- Books Scraping/scrape.py (trimmed)
import requests, math from bs4 import BeautifulSoup import pandas as pd base_url = "https://books.toscrape.com/" def get_categories(): soup = BeautifulSoup(requests.get(base_url).content, "lxml") categories = soup.find("ul", class_="nav nav-list").find("ul").find_all("li") names = [c.a.text.strip() for c in categories] keys = [n.lower().replace(" ", "-") + "_" + str(i+2) for i, n in enumerate(names)] return dict(zip(names, keys)) # "Travel" → "travel_2" def scrape_books(category): url = base_url + "catalogue/category/books/" + get_categories()[category] + "/index.html" soup = BeautifulSoup(requests.get(url).content, "lxml") total = int(soup.find("form", class_="form-horizontal").find("strong").text) pages = math.ceil(total / 20) # 20 books per page all_books = pd.DataFrame() for page in range(1, pages + 1): page_url = url if page == 1 else f"{url[:-10]}page-{page}.html" soup = BeautifulSoup(requests.get(page_url).content, "lxml") names = [h.a.get("title") for h in soup.find_all("h3")] prices = [p.text.lstrip("£") for p in soup.find_all("p", class_="price_color")] ratings = [r["class"][1] for r in soup.find_all("p", class_="star-rating")] books_df = pd.DataFrame({ "Book Name": names, "Price": prices, "Rating": ratings }) all_books = pd.concat([all_books, books_df], ignore_index=True) return all_books
soup.find_all / .find

BeautifulSoup turns HTML into a tree you interrogate with find (one) and find_all (many) — by tag, by class_, or by plain attribute like the rating classes.

math.ceil(total / 20)

Fifty-one books means three pages — ceil rounds up so the last partial page is still visited.

dict(zip(names, keys))

Module 02's zip pops up to build the category lookup — two parallel lists become one mapping.

pd.concat per page

Each page becomes a small DataFrame; they're stacked with ignore_index=True so row numbers stay continuous.

Then the payoff of having a DataFrame: app.py wraps the whole thing in a Streamlit dropdown so anyone can browse a category.

CODE/04- Books Scraping/app.py
import streamlit as st from scrape import scrape_books, get_categories st.title("Books Scraping App") category = st.selectbox("Select a category:", get_categories().keys()) st.markdown(scrape_books(category).to_markdown(index=False))
A tiny sneak preview

Streamlit gets its own module (07). st.selectbox + st.markdown is already a working tool here — run streamlit run app.py and you have a dashboard.

P7Guess the Word

28:26 — the second word game: a redesign with rules, a 10-attempt limit, and a screen that clears between rounds.

Same idea as P1, but this is where the course shows a game getting polished. Compare the two side by side:

P1 · Guessing Game

  • Ends when the whole word is guessed.
  • Counts attempts and reports them.
  • Validates single-letter input.
  • display_word builds a string with dashes.

P7 · Guess the Word

  • Shows a welcome + rules screen.
  • Hard limit of 10 attempts — fail and the word is revealed.
  • Clears the screen (sleeps, then os.system('cls')) each round.
  • Ends the same game by comparing set sizes.
CODE/01- Word Guess/guess_word2.py (trimmed)
import random, time, os allowed_attempts = 10 def clear_screen(): time.sleep(0.8) # let the last message be read os.system('cls') # 'clear' on macOS / Linux def display_word(word, guessed_letters): for letter in word: print(letter if letter in guessed_letters else "-", end="") def guess_word(): word = random.choice(["apple", "banana", "orange", "grape"]) guessed_letters = set() attempts = 0 while True: guess = input("\nEnter a letter: ") attempts += 1 if guess in word: guessed_letters.add(guess) else: print("Wrong guess!") clear_screen() display_word(word, guessed_letters) if len(guessed_letters) == len(set(word)): # every distinct letter found print(f"\nYou guessed the word {word} correctly!") break elif attempts == allowed_attempts: # out of lives print(f"\nYou have exhausted all {allowed_attempts} attempts.") print(f"The correct word was {word}.") break
Small functions again

clear_screen and display_word are one-job helpers — the code actually got easier to follow while the game got richer.

len(set(word))

The win condition collapses letters like "banana" to its distinct set so repeated letters are only guessed once.

Attempt budget

A second exit route (elif attempts == allowed_attempts) means the loop always terminates — the "how does this loop end?" question from Module 02.

os.system('cls')

Runs a shell command to clear the terminal — a platform quirk ('cls' on Windows, 'clear' elsewhere) worth a comment so you remember why.

What the whole module added up to

Seven projects, three basic ingredients: functions (one per feature), a loop (menu or game), and a main guard. From there you stacked on new tools — random, requests + JSON, BeautifulSoup, pandas, streamlit — while while True, break/continue, zip, enumerate, sets and dicts did the heavy lifting. That's the whole idea of the bootcamp: small tools, composed.

Before you move on — common beginner traps

Trusting the player: int(input(...)) crashes on non-numeric input. Wrap risky reads in try/except or validate the string first (P1 does this with isalpha()).

Forgetting keys are secrets: never commit a weather or news key. Use an environment variable as P5 does, and .gitignore your .env.

If statements that overwrite instead of branch: assign balance inside deposit_money without global and you'll shadow it silently — the ATM "stops working" with zero error message.

Ignoring the loop's exit: every while True must have at least one break reachable from real inputs — check P3 (choice 4) and P7 (win or attempts out).

Slicing internals you can't see: scraping depends on the current HTML of a page. Selectors can break when a site redesigns — that's normal, re-inspect with a fresh soup.
