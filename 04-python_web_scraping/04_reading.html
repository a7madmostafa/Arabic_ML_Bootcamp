1Web scraping intro — the theory

Understanding scraping as the browser's request minus the browser's rendering.

What it is

Web scraping is a technique to access and extract information from a website — pulling the source code out of a page and grabbing specific parts of it.

Why use it

  • Collect data not available through an API.
  • Automate data collection — save time and effort.
  • Collect data that is updated dynamically, over and over.
Is scraping legal?

Guidance from the lecture, not legal advice: scraping is legal as long as you're not violating the website's terms of service. If the site has no terms of service, you should be fine. One concrete cost either way: every request consumes server resources for the host website — scrape politely.

1.1 A web page is three languages

ComponentRole
HTMLThe markup language that defines the structure of the page.
CSSThe language that defines the style of the page.
JavaScriptThe language that defines the behavior of the page.

1.2 HTML is a tree

HTML documents nest elements inside each other like a tree. The root element is <html>, it branches into <head> (metadata — the title) and <body> (the visible content), and headings and paragraphs nest further inside the body. Here is the skeleton from the notes:

page skeleton
<html> <head> <title>Page Title</title> </head> <body> <h1>Heading 1</h1> <p>Paragraph 1</p> <p>Paragraph 2</p> <p>Paragraph 3</p> </body> </html>
<html>

The root element of every page.

<head>

Stores page metadata, including the title.

<body>

Contains the visible page content — headings and paragraphs nested inside.

1.3 Classes identify many, IDs identify one

CSS class

Identifies multiple elements that should look or behave the same — two different tags can share class="card".

CSS ID

Identifies a single unique element — id="search" should appear at most once per page.

selectors in raw HTML
<p class="card">Paragraph 1</p> # both use the same class <h2 class="card">Heading 2</h2> <p id="first">Paragraph 1</p> # one element, one id

1.4 How scraping actually works

Your code does the same thing a browser does — it sends a server request with a specific URL and asks the server to return the code for that page. The difference: the browser interprets HTML/CSS/JS and paints a visual page; your scraper filters the source code looking for the elements you specified, and extracts whatever content it wants. Step by step, that exchange is:

  1. The client sends a request to a server.
  2. The request includes a specific URL.
  3. The server processes the request.
  4. The server returns a response containing the page code.

The four-step workflow

  1. Choose a web page URL.
  2. Send a request — the server returns the page's source code, usually HTML.
  3. Parse the HTML into a searchable tree.
  4. Locate the target elements and extract the required data.

1.5 Actual response vs. visual browser output

The server's answer and what the browser paints are related — but not the same thing. Your scraper only ever sees the tree of tags; the browser interprets that same tree into a rendered page.

Server response

The server returns source code such as HTML. Here's a real snippet in the shape this module scrapes:

<div class="css-example"> <h2 class="job-title"> <a href="/jobs/machine-learning-engineer"> Machine Learning Engineer </a> </h2> <div class="company"> <a href="https://example.com/company">Edentech</a> </div> </div>

Browser output

The browser interprets the HTML, CSS, and JavaScript, then displays a rendered page — a job card with a clickable title and company name — where your scraper only sees the tags above.

2Coding 01 — your first scrape

Fetch the Wuzzuf machine-learning job board and pull every job title, link, company and spec off it.

Web_Scraping.ipynb
import requests from bs4 import BeautifulSoup response = requests.get('https://wuzzuf.net/search/jobs/?q=machine+learning&a=hpb') soup = BeautifulSoup(response.content, 'lxml')
requests

Does the GET — the same server request a browser would make. response.content holds the raw HTML bytes.

BeautifulSoup

Parses those bytes into a navigable tree. The 'lxml' parser is fast and permissive with messy real-world HTML.

soup

Inspecting soup in the notebook shows the entire page source, nicely indented — that's what you'll be searching through.

2.1 find() vs. find_all()

find() returns the first match; find_all() returns a list of every match. You'll typically find() to probe one element, then switch to find_all() to collect the whole batch. Note the double-quoted attribute dictionary.

first vs. all
title = soup.find("h2", {'class': 'css-m604qf'}) # first job title element print(title.a.text) # the text of its one <a> child titles = soup.find_all("h2", {'class': 'css-m604qf'}) # all titles print(titles[0].text)

2.2 Building the five parallel lists

Each <a> inside a title <h2> carries a relative URL, so full links are assembled by prepending the origin. Companies and occupation specifiers are separate elements with their own classes, extracted the same way.

titles, links, occupations, companies, specs
titles_lst = [title.a.text for title in titles] links = ['https://wuzzuf.net' + title.a['href'] for title in titles] occupations = soup.find_all("div", {'class': 'css-1lh32fc'}) occupations_lst = [occupation.text for occupation in occupations] companies = soup.find_all("a", {'class': 'css-17s97q8'}) companies_lst = [company.text.replace(' -', '') for company in companies] specs = soup.find_all("div", {'class': 'css-y4udm8'}) specs_lst = [spec.text for spec in specs]
title.a['href']

Attribute access: tag['attr']. Job links on Wuzzuf are relative, so each is prefixed with the origin.

.text vs .a.text

title.text would include nested whitespace; going straight for title.a.text grabs only the anchor's text.

.replace(' -', '')

Company names print with a trailing -; a tiny cleanup makes the list DataFrame-ready.

2.3 From dict to DataFrame to CSV

packaging the results
scraped_data = {} scraped_data['Title'] = titles_lst scraped_data['Link'] = links scraped_data['Occupation'] = occupations_lst scraped_data['Company'] = companies_lst scraped_data['Specs'] = specs_lst import pandas as pd df = pd.DataFrame(scraped_data) df.to_csv('mljobs.csv', index=False)
Why a dict of equal lists?

A pandas DataFrame is a dict of columns — so building scraped_data as {'ColumnName': [row, row, ...]} maps one-to-one onto pd.DataFrame(scraped_data). Five equal-length lists become a 5-column table.

3Coding 02 — pagination & helper functions

One page of results is a toy; this lecture turns the notebook into a reusable helper module that walks every page of a query.

Web_Scraping.ipynb
import requests, math from bs4 import BeautifulSoup query = 'data scientist' query = query.replace(' ', '%20') url = 'https://wuzzuf.net/search/jobs/?q=' + query + '&a=hpb' response = requests.get(url) soup = BeautifulSoup(response.content, 'lxml')

3.1 Reading the total job count

Wuzzuf prints something like "1–15 of 189 Jobs" in a <li> element. Splitting on 'of ' isolates the number, and dividing by the 15-jobs-per-page gives the number of pages — rounded up with math.ceil(), because a partial last page still needs fetching.

jobs → pages
s = soup.find("li", {'class': 'css-8neukt'}).text print(s) # 1–15 of 189 Jobs jobs = int(s.split('of ')[1]) print(jobs) # 189 import math pages = math.ceil(jobs / 15) # 13

3.2 Looping over pages with &start=

Wuzzuf's URL accepts a start parameter — page 0, page 1, page 2 … Re-scraping the same five lists per page and concatenating with += collects all results into one big dataset.

paginated scrape
titles_lst, links_lst = [], [] for pageNo in range(pages): page = requests.get( 'https://wuzzuf.net/search/jobs/?q=' + query + '&start=' + str(pageNo) ) soup = BeautifulSoup(page.content, 'lxml') titles = soup.find_all("h2", {'class': 'css-m604qf'}) titles_lst += [title.a.text for title in titles] links_lst += ['https://wuzzuf.net' + title.a['href'] for title in titles] # ...occupations, companies, and specs the same way

3.3 The helper module

Everything gets refactored into scrap_helper.py: find_no_of_jobs() returns the count and page count, scrap_pages() returns (scraped_data, df) for one query, and two combiners merge results from several queries.

combine_dfs

def combine_dfs(dfs): df = pd.concat(dfs) df = df.drop_duplicates() return df

combine_dicts

def combine_dicts(dicts): combined = {} for key in dicts[0].keys(): combined[key] = [] for d in dicts: combined[key] += d[key] return combined
Splitting on the right character

The notebook previews specs like "Full Time · 2 – 3 Years · ..." — the pieces are separated by the · character. A quick loop printing len(spec.text.split(' · ')) per spec verifies every row splits into the same number of fields before you build the DataFrame.

4Coding 03 — the production script

The finished, runnable version: one function that scrapes, packages, and saves — guarded so it only runs when executed directly.

scrap_jobs.py
import requests from bs4 import BeautifulSoup import pandas as pd def scrap(): response = requests.get( 'https://wuzzuf.net/search/jobs/?q=machine+learning&a=hpb') soup = BeautifulSoup(response.content, 'lxml') titles = soup.find_all("h2", {'class': 'css-m604qf'}) titles_lst = [title.a.text for title in titles] links = ['https://wuzzuf.net' + title.a['href'] for title in titles] occupations = soup.find_all("div", {'class': 'css-1lh32fc'}) occupations_lst = [occupation.text for occupation in occupations] companies = soup.find_all("a", {'class': 'css-17s97q8'}) companies_lst = [company.text for company in companies] specs = soup.find_all("div", {'class': 'css-y4udm8'}) specs_lst = [spec.text for spec in specs] scraped_data = { 'Title': titles_lst, 'Link': links, 'Occupation': occupations_lst, 'Company': companies_lst, 'Specs': specs_lst, } df = pd.DataFrame(scraped_data) df.to_csv('mljobs.csv', index=False) print("Jobs Scraped Successfully") return df if __name__ == '__main__': scrap()
one function, five fields

The entire pipeline squeezed into a single scrap() — request, parse, five list comprehensions, DataFrame, CSV.

if __name__ == '__main__'

Importing the script elsewhere runs scrap() only when executed as a program — the Module 02 pattern for import-safe scripts.

the takeaway

Coding 01 per line, coding 02 generalized it to many pages, coding 03 made it re-runnable. That progression — explore → generalize → productionize — is the actual skill this module teaches.
