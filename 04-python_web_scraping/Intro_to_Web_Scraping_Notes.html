1What is web scraping?

A technique for pulling data out of a website.

Web scraping is a technique used to access and extract information from a website. Rather than reading a page visually, a scraper reads its source code.

2Why web scraping?

The three reasons the lecture gives.

No API? No problem

Collect data that is not available through an API.

Automation

Automate collecting data — saving time and effort.

Live data

Collect data that is updated dynamically, so the dataset stays fresh.

3Is web scraping legal?

Not legal advice

The following reproduces the guidance presented in the source material: scraping is legal as long as you are not violating the website's terms of service. If the website has no terms of service, you should be fine. Either way, remember that scraping consumes server resources for the host website.

4Components of a web page

Every page is three languages working together.

ComponentPurpose
HTMLThe markup language that defines the structure of a web page.
CSSThe language that defines the style of a web page.
JavaScriptThe language that defines the behavior of a web page.

5HTML tree structure

HTML documents are organized as a tree of nested elements.

<html>

The root element of every page.

<head>

Stores page metadata, including the title.

<body>

Contains the visible page content — headings and paragraphs nested inside.

6CSS classes and IDs

The two selectors you'll be matching with BeautifulSoup.

CSS class

A class can identify multiple elements.

<p class="class1">Paragraph 1</p> <h2 class="class1">Heading 2</h2>

CSS ID

An ID identifies a single element.

<p id="id1">Paragraph 1</p>
Selector typeIntended use
ClassIdentifies multiple elements.
IDIdentifies one element.

7How web scraping works

The same request a browser makes — without the rendering.

vs. a real browser

We're essentially doing the same thing a web browser does — sending a server request with a specific URL and asking the server to return the code for that page. But the code does not interpret the source and display it visually. Instead, custom code filters through the source looking for the specific elements we've specified, extracting whatever content we want.

8Actual response vs. visual browser output

The server's answer and what the browser paints are related — but not the same thing.

Server response

The server returns source code such as HTML. Here's a real snippet in the shape this module scrapes:

<div class="css-example"> <h2 class="job-title"> <a href="/jobs/machine-learning-engineer"> Machine Learning Engineer </a> </h2> <div class="company"> <a href="https://example.com/company">Edentech</a> </div> </div>

Browser output

The browser interprets the HTML, CSS, and JavaScript, then displays a rendered page. A scraping script usually processes the source code instead of painting anything visually.

While the browser sees: a job card with a clickable title and company name —

your scraper only sees the tree of tags above.

9Web-scraping workflow

The four-step procedure the notes lay out.

The pipeline

  1. Choose a web page URL.
  2. Write code that sends a request to the server hosting that page.
  3. The server returns the page's source code — usually HTML.
  4. Parse the HTML, locate the target elements, and extract the required data.
The key idea

Unlike a web browser, web-scraping code does not necessarily interpret the source code and display the page visually. Instead, it parses the returned HTML to locate and extract data. The reading page's lectures show exactly how — first element, then page, then every page.
